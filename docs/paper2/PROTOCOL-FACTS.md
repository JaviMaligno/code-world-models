# The LLM protocol, completely (appendix source fragment)

Review point #17: the paper describes the synthesis pipeline in prose but never
states the protocol completely enough to reimplement. This file is the complete
specification, **extracted from the code, not written from memory**. Every claim
carries the `file:line` it was read off (line numbers as of 2026-07-27). All
numbers come from `results/llm_protocol_facts.json`, regenerated by
`scripts/llm_protocol_facts.py` — nothing here is hand-counted.

Everything below applies to `scripts/continuous_danger_synthesis.py`, the script
behind every §6–§10 synthesis campaign of paper 2. The agent-relayed Claude arms
use the same message text but a different transport (§10 of this file).

---

## 1. The two messages

### 1.1 System message (synthesis call only)

`src/cwm/continuous/contract.py:87-89`, one string, sent verbatim:

```
You are an expert Python programmer. You write deterministic, pure code that exactly implements a specified physics world model. Output ONLY a single Python code block, no prose.
```

### 1.2 Synthesis user message

`src/cwm/continuous/contract.py:90-98`. The template, with `{...}` slots:

```
{contract}

Here are observed transitions (ground truth) to match exactly:
{example_lines}

{guidance}

Write the Python module implementing the contract. Output only one ```python code block.
```

* `{contract}` = `build_contract(env, include_mode)` = the instrument's API text
  (pinned integrator equations, in order) + its rules text (physical constants,
  reward, and — in the **full** arm only — the mode clause).
  `contract.py:32-34`, text in `src/cwm/continuous/instruments.py`.
* `{guidance}` is the confound-closure knob. It is `""` in every default run,
  and the `extra = f"{guidance}\n\n" if guidance else ""` construction
  (`contract.py:90`) means an empty guidance leaves the message **byte-identical**
  to the pre-knob prompt. Asserted by
  `tests/test_continuous_contract.py::test_guidance_default_is_byte_identical_and_insertion_is_clean`
  and, at the level of the variant table, by
  `tests/test_prompt_variants.py::test_default_variant_entry_is_the_original_prompt_byte_for_byte`.
* The messages list is exactly `[system, user]` (`contract.py:97-98`).

### 1.3 Example lines: how many, and which

`contract.py:67-76`. One line per shown transition:

```
step({state!r}, {action!r}) -> {next_state!r}   reward(next) = {reward!r}
```

`repr()` is used throughout, so full float precision is shown. Selection is a
**stride over the whole sample**, not a prefix (a prefix would come from a single
rollout): `idx = sorted({(i * n) // max_examples for i in range(min(max_examples, n))})`
(`contract.py:71`).

At the campaign default N = 40 rollouts and `h_episode = 80`, the sample is
**3200 transitions** on all three instruments, and the prompt shows

| `max_examples` | example lines | fraction of the sample shown |
| --- | --- | --- |
| 30 (default) | 30 | 0.937 % |
| 120 (guided/region/landing) | 120 | 3.75 % |

(`results/llm_protocol_facts.json` → `example_budget`.) The **gate**, by contrast,
always uses all 3200 transitions (`contract.py:167-177`) — the model is shown ~1 %
of the evidence it is scored on.

### 1.4 Refine user message

`contract.py:200-206`. There is **no system message** on a refine call (outer
fence widened to four backticks because the message itself contains fences):

````
{contract}

The current implementation is below. It fails some transitions. Fix it so every transition matches to within {eps} in x, v and reward. Output only one ```python code block.

CURRENT CODE:
```python
{code}
```

FAILURES (expected vs got):
{first max_failures failure lines}

{guidance}
````

Each failure line is produced by `_compare_transitions` (`contract.py:135-164`)
and is one of

* `step({state!r}, {action!r}) raised {exc!r}`
* `step(...): wrong state arity: expected {k} components, got {m}`
* `step(...): expected {next_state!r} r={reward!r}, got {got!r} r={got_r!r} (err {err:.3g})`

**Truncation.** Only the first `max_failures` lines are shown:
`"\n".join(failures[:max_failures])` (`contract.py:205`). Default
`max_failures = 20` (`contract.py:191`); the guided/region/landing variants use
40. Failures are in sample order (the order `collect_transitions` produced), so
the truncation keeps the *earliest* failures, not the worst ones.

**Wart worth recording:** the sentence says "in x, v and reward" on every
instrument, including the 4-D PatchField2D whose state is `[x, y, vx, vy]`
(`contract.py:202`). The tolerance actually enforced is the sup-norm over *all*
state components and the reward (`contract.py:154-155`), so the text understates
the check on the 2-D instruments. This is the text used by every committed run.

## 2. The refine loop

`contract.py:188-214`.

* Termination: `while acc < 1.0 and iterations < max_iters` (`contract.py:199`),
  where `acc = contract_accuracy(code, transitions, eps)` over the **whole**
  sample. The loop stops on the first artifact that matches every transition to
  `eps`, or when the budget runs out — nothing else can stop it.
* `eps = 1e-9` in every committed campaign, against a **pinned** integrator, so
  the gate is effectively exact match.
* Iteration budget per campaign: `--max-iters`, default **5**
  (`scripts/continuous_danger_synthesis.py:306`). The two region-guidance
  campaigns used **15** (`*_pv-region_it15`, the 3× budget arm). No other value
  appears in `results/`.
* **The loop is memoryless.** Each iteration sends exactly one message —
  `provider.complete([{"role": "user", "content": msg}], model=model)`
  (`contract.py:207-208`) — freshly built from `(contract, current code,
  current failures)`. No conversation history, no system message, no assistant
  turns are carried across iterations. The only state passed forward is the
  code string itself. Asserted by
  `tests/test_prompt_variants.py::test_llm_calls_per_seed_is_one_plus_refine_iterations`
  (checks the role sequence is `[system, user]` on call 0 and `[user]` on every
  refine call).
* `refine_iterations` recorded per cell = the number of refine calls issued
  (`contract.py:212`, `contract.py:304`). It equals `max_iters` exactly when the
  budget was exhausted without reaching accuracy 1.0.

## 3. Code extraction, and an unparseable reply

`src/cwm/synthesizer.py:28-35`, used for both message types
(`contract.py:290`, `contract.py:210`):

1. first ` ```python ... ``` ` block, if any → its body, trailing newlines stripped;
2. else the first fenced block that is **not** tagged `python`;
3. else the whole reply, `.strip()`ed.

So there is **no parse failure path**: a reply with no code block is passed on as
if it were code. What happens next is that it fails the gate rather than raising:

* `contract_accuracy` runs the candidate in a sandbox subprocess
  (`contract.py:101-132`); if the sandbox fails, produces no output, or prints
  non-JSON, accuracy is `0.0` and the single "failure line" is the error text
  (`contract.py:173-175`). The refine loop then continues normally.
* In the separate audit path, such an artifact is classified `invalid` —
  `ast.parse` raising `SyntaxError`, or a missing/uncallable `step`/`reward`, or
  a raising trivial call (`src/cwm/continuous/artifact_class.py:90-113`, preflight
  at `:59-88`). `invalid` is deliberately kept distinct from `gate_failing`.
* Nothing in the pipeline retries a reply because it was unparseable, and nothing
  discards a cell for it.

## 4. Retry and error policy

* **Transport-level retries only, from the OpenAI SDK.**
  `AzureOpenAIProvider(max_retries=6, timeout=120.0)`
  (`src/cwm/llm/azure_openai.py:10-16`) and
  `OpenAICompatProvider(max_retries=6, timeout=300.0, max_tokens=8192)`
  (`src/cwm/llm/openai_compat.py:11-16`). The SDK does exponential backoff and
  honours `Retry-After`; the wrappers only raise the ceiling from the SDK default
  of 2.
* **No application-level retry, and no error swallowing.** There is no
  `try`/`except` anywhere around `provider.complete` in
  `src/cwm/continuous/contract.py` or in
  `scripts/continuous_danger_synthesis.py`. A refusal (`no choices`) or missing
  usage metadata raises `ValueError`
  (`azure_openai.py:21-25`, `openai_compat.py:21-22`), and the exception
  propagates out of the sweep loop and kills the run.
* **What that costs.** Nothing already computed: the sweep checkpoints atomically
  after *every* cell (`continuous_danger_synthesis.py:179`, temp file +
  `os.replace`) and skips already-present `(arm, seed_index)` pairs on restart
  (`:155-160`), refusing to resume a file produced under different
  result-defining flags (`:125-146`). So a crashed campaign is restarted, not
  re-paid for.
* Consequence for the paper: **there is no cell in `results/` that was retried,
  resampled, or dropped because of a provider error.** Every cell is the first
  and only draw for its `(arm, seed)`.

## 5. Sampling parameters actually sent

Read off the `chat.completions.create(...)` call sites
(`results/llm_protocol_facts.json` → `provider_sampling_params`):

| wrapper | kwargs sent | temperature | top_p | seed |
| --- | --- | --- | --- | --- |
| `azure_openai.py:20` | `model`, `messages` | **not set → provider default** | not set | not set |
| `openai_compat.py:19-20` | `model`, `messages`, `max_tokens=8192` | **not set → provider default** | not set | not set |

`azure_openai.py:19` records why: *"NOTE: no temperature/top_p — GPT-5.4 rejects
them."* So the runs are **not** temperature-0: they are whatever the deployment's
default sampling is, which is why the campaigns are reported as distributions
over seeds rather than as single deterministic artifacts. There is no request-level
`seed`, so the LLM half of the pipeline is **not** reproducible bit-for-bit; the
*sample* half is (rollout seed `10_000 * (i + 1 + seed_offset)`,
`continuous_danger_synthesis.py:164`), and the synthesized code of every cell is
versioned in the result JSON, so every reported number is re-derivable from the
artifacts even though a re-run would draw new ones.

## 8. What the gate is

`contract.py:285-308`, per cell:

1. `collect_transitions(env, n_rollouts=40, seed=10_000*(i+1+offset))` — N i.i.d.
   uniform-random rollouts on the truth; **the same transitions are the training
   examples and the gate** (`contract.py:37-57`).
2. synthesize → refine (§2) → `gate_accuracy = refined.accuracy`,
   `gate_passed = (accuracy == 1.0)`.
3. `sample_contains_wall` / `sample_contains_mode_per` — the identifiability
   event, logged per cell (`contract.py:60-64`, `instruments.py` `sample_modes`).
4. `mode_blindness` (`contract.py:238-265`), computed **only** when the gate
   passed: the fraction of mode-region probe transitions the artifact gets wrong,
   per mode, at `eps = 1e-6`. Probes fire their mode in truth by construction and
   this is asserted at runtime (`contract.py:253`). Single-mode instruments emit a
   scalar under the key `wall_blindness`; PatchField2D emits the per-mode dict
   `mode_blindness` and puts its mean in `wall_blindness`.

## 9. Artifact classification: the operational rules

These are the *executable* definitions, not paraphrases.

### repaired

Two levels, both used in the paper, and they are **not the same predicate**:

* 1-D instruments (cart, pendulum) —
  `scripts/audit_paper2_numbers.py:368-371`:
  ```python
  gate_passed and (wall_blindness or 0) == 0.0
  ```
  i.e. the gate reached accuracy 1.0 **and** every mode probe is reproduced
  exactly. Denominator: cells with `arm == "incomplete"` and
  `sample_contains_wall` true.
* PatchField2D — `scripts/audit_paper2_numbers.py:296`:
  ```python
  repaired = [c for c in mode_present if c["gate_passed"]]
  ```
  i.e. gate passage alone, over cells whose sample contained *some* mode
  (`any(sample_contains_mode_per.values())`). This is the *weaker* test, and it
  is the honest one to quote for the 0/76: not one artifact even reached
  accuracy 1.0, so no blindness test was needed to reject it.

### blind / superstitious-patch / disc-form (behavioral, `scripts/patch2d_artifact_audit.py`)

All three are decided by probing the artifact's `step` on a grid and comparing
against the pure integrator — **behaviorally, not by reading the source**.
Instrument (`:51-55`): grid `81 x 81` over `x ∈ [-2, 14]`, `y ∈ [-8, 8]`, action
`0.3`, deviation threshold `EPS_DEV = 1e-6`, two velocity slices `(vx, vy) =
(0, 0)` and `(1.5, 0.5)` (`:191-192`). `m0` is the zero-velocity deviation mask;
`n0`, `n1` are the deviating-cell counts.

| class | operational rule | line |
| --- | --- | --- |
| `invalid` | `exec` raises, `step` missing, or `len(step(...)) != 4` | `:183-189` |
| `crash` | mask construction raises | `:190-194` |
| `blind` | `n0 == 0 and n1 == 0` **and** `step`'s body has no `if` | `:234-237` |
| `blind-textual-patch` (the paper's **superstitious patch**) | `n0 == 0 and n1 == 0` **and** `step`'s body *does* contain an `if` (`_step_has_conditional`, `:170-175`) — a written rule whose trigger set is behaviorally empty, e.g. an exact-coordinate trap, which is measure-zero and therefore never fires | `:234-236` |
| `vdep` | `n0 == 0` but `n1 > 0` — deviates only at nonzero velocity | `:238-240` |
| `point` | largest connected component `< 0.5` world-units² | `:244-247` |
| `halfplane` | largest component reaches the far-east column or top/bottom row of the probe window (unbounded proxy, `_touches_far_edge`, `:161-167`) | `:252-254` |
| `square-form` | bounded, `bbox_fill >= 0.90` | `:257-258` |
| **`disc-form`** | bounded, `0.62 <= bbox_fill < 0.90` **and** `radial_ratio <= 1.30` (π/4 ≈ 0.785 is a disc's bbox fill; `radial_ratio` = max/min radial extent over 16 angular bins about the centroid, `_shape_metrics`, `:139-158`) | `:259-260` |
| `bounded-other` | bounded, neither of the above (ellipses, hulls, unions, arcs) | `:261-262` |

Components are 4-neighbour connected (`:115-136`); classes are mutually exclusive
and exhaustive, evaluated in the order above. The classifier is validated against
constructed artifacts of known class in `--selftest` (`:427-459`), which builds a
blind artifact, a half-plane, a disc, a square, a velocity-dependent freeze, a
point trap and an exact-coordinate trap and asserts the returned class.

Two derived per-artifact quantities the paper leans on:

* `cover_p1` / `cover_p2` — fraction of the **true** patch's grid cells that the
  artifact's `m0` mask covers (`:199-209`). "Contains the seen patch" in the
  paper means `cover > 0.9`; "patch-selective" means additionally
  `cover(unseen) < 0.1` (`:400-402`).
* `integrator_exact` — no *numeric* (non-freeze-form) deviation anywhere west of
  `x = 1`, i.e. deviations there that preserve position and zero velocity count
  as an overreaching mode rule rather than wrong arithmetic (`:216-233`).

## 10. The agent-relayed Claude arms

## 11. Prompt variants (the confound-closure arms)

`scripts/continuous_danger_synthesis.py:198-240`. Each variant sets exactly three
knobs — `max_examples`, `max_failures`, `guidance` — and nothing else; the
contract text is never touched by a variant (`build_contract` does not take
`guidance`), so no variant can leak the mode clause.

| variant | `max_examples` | `max_failures` | guidance |
| --- | --- | --- | --- |
| `default` | 30 | 20 | `""` — byte-identical to every committed run |
| `guided` | 120 | 40 | describe-the-region-first process guidance (`:198-204`) |
| `region` | 120 | 40 | `guided` + "the trigger region need not be a 1-D threshold" de-bias (`:205-210`) |
| `landing` | 120 | 40 | `region` + **one sentence** naming the trigger's argument (`:221-225`) |

The `landing` sentence, verbatim (`:221-225`):

> A localized rule's trigger is evaluated on the state the integrator WOULD
> produce for this step — the landing position (x2, y2) from the integrator
> equations above — not on the position the step began at (x, y).

It exists because the audit of the 40 region-guidance artifacts found **36/40**
conditioning the freeze rule on the *current* position instead of the landing
position `(x2, y2)`, the causal variable of the true rule — a
variable-identification failure, which is a different failure from getting the
region's geometry wrong. The sentence names only the argument: it uses the
variable names the contract's own integrator block already introduces and states
nothing about the region's shape, centre, radius, or count.
`tests/test_prompt_variants.py` asserts this isolation four ways — the delta over
`region` is exactly one sentence; it contains no shape word and none of the
truth's numeric constants; no line that the full (mode-stating) contract adds
over the incomplete one appears in any variant's guidance; and the guidance
inserts into both the synthesis and the refine message without moving anything
else.
